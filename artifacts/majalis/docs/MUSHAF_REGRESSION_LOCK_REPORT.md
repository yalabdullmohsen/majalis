# تقرير قفل ارتداد المصحف — MUSHAF_REGRESSION_LOCK

**الفرع:** `fix/mushaf-regression-lock` · **الوسم:** `safe:ui`  
**التاريخ:** 2026-08-10

## إجابة صريحة: لماذا خضرّت البوابات والعيبان ظاهران؟

### ١) بوابة اللقطة البصرية كانت مخرج هروب في CI

في `mushaf-ref-visual-gate.mjs` (قبل الإصلاح)، عند `CI`/`GITHUB_ACTIONS` ونجاح الفحوص الهيكلية فقط، كان فرق PNG يُتجاهل ويُستبدل بفحص استقرار ذاتي (gen مقابل gen2):

```js
if (onCi && structuralOk) {
  // مراجع PNG مقفلة على macOS؛ على Linux CI نثبت استقرار اللقطة + الهيكل.
  // … selfCmp فقط — لا يفشل على فرق المرجع …
}
```

النتيجة: لقطة محلية/إنتاج تختلف ١٢–١٥٪ عن المرجع بينما CI يقول OK. **هذا سبب عودة انضغاط ص١–٢ وتراكب الخرطوش بعد إصلاحات سابقة.**

**التصحيح:** أُزيل مخرج CI بالكامل. أي فرق ظلّي >٢٪ يفشل البناء ما لم يُمرَّر `MUSHAF_UPDATE_REFS=1` لتحديث المراجع عن قصد. الصفحات المقفلة الآن: `1 · 2 · 3 · 50 · 235 · 283 · 601`.

### ٢) قياس الحبر المعطوب في بوابات الافتتاح/النطاقات

`measureInkBounds` / تقدير canvas+منتصف الصندوق كان يمرّر فجوات «حبر» موجبة بينما **صناديق الأسطر متراكبة** (`OPENING_BODY_SLOT_H_PCT = 5.4` أصغر من ارتفاع السطر الفعلي ~٤٦px).  
بوابة النطاقات كانت تفشل فقط عند `badgeInk.oy > 0.5` دون إلزام مسافة ≥٢٨px.

**التصحيح:** فجوات حبر عبر `Range`/`getClientRects`، خانة جسم ٥٫٨٪، تموضع يعيد توزيع الأسطر فوق `badgeTop − 28`، و`--mpv-content-footer-gap: 28px`.

## ما تغيّر وظيفياً

1. **ص١–٢:** إعادة تموضع موحّد (شارة ٣٨٪ · فواصل ٢٤/٢٠ · فجوات متساوية · تثبيت فوق الخرطوش).
2. **خرطوش:** `contentFooterGapPx = 28` + بوابة ≥٢٨px + عيّنة كثيفة في `layout-bands`.
3. **لقطة بصرية:** ٧ صفحات · عتبة ٢٪ · بلا مخرج CI.
4. **تحديد الآية:** هالة ذهبية على `.mf2-word` (١٠٪ / ٦px / ظل) · ١٤٠ms · ليلي ١٦٪ · بلا إزاحة أساس.
5. **شيت التفسير/القرّاء:** `MushafReaderOptionsSheet` — أقسام + بحث `tolerantIncludes` + المختار مثبت + إغلاق سفلي.
6. **اللفّ:** يبقى وفق المواصفة (١٠° · 1200px · ٢٤٠ms · عتبة ١٨٪) — اختبار الوحدة أخضر.
