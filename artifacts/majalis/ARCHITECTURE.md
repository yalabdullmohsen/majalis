# بنية `artifacts/majalis/src` — أين يوضع الملف الجديد؟

آخر تحديث: 2026-08-08 (مرحلة التنظيف 4)

## المبدأ

ملف واحد = مكان واحد. لا تُنشئ مكوّناً موازياً في مجلد آخر لنفس الغرض.

| المجلد | الغرض | أمثلة |
|---|---|---|
| `features/<name>/` | ميزة مكتملة (منطق + UI خاص بالميزة) | بحث، مسارات تعلم، تسميع |
| `views/` | صفحات التوجيه فقط (غلاف مسار → يستدعي feature/pages) | `AdminPage`, صفحات قائمة |
| `pages/<domain>/ui/` | مشاهد صفحة حسب المجال (حساب، قرآن، مكتبة…) | `HomeView`, `LibraryView` |
| `ui-common/` | مكوّنات UI مشتركة بين أكثر من ميزة | `IslamicDivider`, `RulingCard` |
| `components/` | مكوّنات عامة قائمة (ترحيل تدريجي نحو `ui-common` / `features`) | NavBar، أخطاء، shadcn تحت `components/ui` |
| `lib/` | أدوات وخدمات بلا JSX (أو بحد أدنى) | supabase، أذان، خدمات محتوى |
| `hooks/` | خطافات React مشتركة | `usePrayerCountdown` |
| `app/` | هيكل التطبيق: providers، router، `styles/theme.css` | نقطة تنظيم ما بعد الترحيل |
| `shared/` | عقود/أنواع/إعدادات مشتركة بين طبقات | config، أنواع |
| `styles/` | CSS غير المضمّن في `@theme` | أنظمة بصرية مساعدة |
| `data/` | فهارس/ثوابت بيانات صغيرة في المصدر | ليست بديل `public/data` |
| `entities/` | كيانات مجال (قراءة/خطافات كيان) | عالم، كتاب |
| `widgets/` | وحدات عرض صغيرة قابلة لإعادة الاستخدام | عناوين أقسام |
| `quran/` / `majlis/` | مجالات ثقيلة خاصة بالمصحف/المجلس | لا تُفرَّغ هنا |

## قاعدة «أين الجديد؟»

1. **صفحة مسار جديدة** → `views/` (غلاف) + التنفيذ في `pages/<domain>/` أو `features/<name>/`.
2. **مكوّن يُستخدم في ميزتين فأكثر** → `ui-common/` (وليس نسخاً داخل كل ميزة).
3. **منطق بلا واجهة** → `lib/` (أو `features/<name>/lib` إن كان خاصاً بميزة).
4. **رمز تصميم (`--background`, `--primary`, `--font-display`…)** → مصدر واحد: `app/styles/theme.css` عبر `@theme`. لا تعريفات متعارضة في `brand-v4` / aliases.
5. **أصول محتوى كبيرة** → `public/data/…` مع تسمية واضحة؛ لا تُحذف ولا تُعاد تسميتها بلا إثبات قاطع لطلب ديناميكي بالاسم.
