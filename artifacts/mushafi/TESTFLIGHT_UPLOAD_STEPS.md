# TestFlight Upload Steps

## 1. Final checks

Run from `artifacts/mushafi`:

```bash
flutter clean
flutter pub get
flutter analyze
flutter test
dart run scripts/check_quran_asset.dart
```

If `scripts/check_quran_asset.dart` does not exist, skip that command and verify Quran assets manually.

## 2. CocoaPods

```bash
cd ios
pod install
cd ..
```

If `pod` is missing (common on macOS with system Ruby 2.6):

```bash
# Prefer Homebrew Ruby + CocoaPods:
brew install ruby cocoapods
# Ensure brew ruby/bin is on PATH, then:
cd ios && pod install && cd ..
```

Alternative:

```bash
sudo gem install cocoapods
cd ios && pod install && cd ..
```

## 3. Open Xcode workspace

```bash
open ios/Runner.xcworkspace
```

Do **not** open `Runner.xcodeproj` when CocoaPods is used.

## 4. Xcode signing

In Xcode:

* Select **Runner**.
* Open **Signing & Capabilities**.
* Select the correct Apple Developer Team.
* Confirm Bundle Identifier: `com.mushafi.mushafi`.
* Confirm build number is unique (from `pubspec.yaml` → `version: x.y.z+BUILD`).
* Confirm **Automatically manage signing** or valid manual signing.

## 5. Archive

From Xcode:

**Product → Archive**

## 6. Upload

After archive completes:

**Organizer → Distribute App → App Store Connect → Upload**

## 7. App Store Connect

After upload processing:

* Open App Store Connect.
* Go to the app.
* Open **TestFlight**.
* Select the processed build.
* Add it to **Internal Testing**.
* Add testers.
* Add testing notes (see `testflight_notes.md`).
* Send invitation.

## Important

* Do not upload the same build number twice.
* Do not upload from `artifacts/majalis`.
* This upload is for `artifacts/mushafi` only.
* Audio upload must stay disabled by default.
* Quran text must not be generated by AI.
* Current marketing version / build in repo: see `pubspec.yaml` (`1.0.0+1` at prep time). If build `1` was already uploaded, bump to `1.0.0+2` before archiving.
